# DSH Project Desktop 0.1.4 — Windows 平台可用性版 / Windows availability

本次发布的重点是让 Windows 与 macOS 行为一致：修好三处只在 Windows 上暴露的缺陷，把插件的测试套件接入 Windows CI，并带上更早的 Mica 材质与项目资源修复。

## Windows

- **修复资源根路径在 8.3 短名下的比较失败**：`fs.realpathSync` 在 Windows 上不展开 8.3 短名，而 `git rev-parse --show-toplevel` 会展开。当工作目录是 `C:\Users\RUNNER~1\…` 这类短名时，两侧 realpath 不相等，添加或检查 Git 资源会误报 `resource-git-invalid`，克隆到已被跟踪的目录也不再报 `target-tracked`，共享 refs 的资源还会重复 fetch。相关比较与去重键现在统一规范化。该缺陷在 macOS 上不可见。
- **插件 setup 在 Windows 上可用**：修复 `spawnSync('corepack.cmd')` 因 Node 的 CVE-2024-27980 限制而静默失败（`status=null`、零输出）；解包运行时归档时不再把绝对路径交给 GNU tar（Git Bash 会把 `-C D:\…` 里的 `D:` 当成远程主机）；CI 的 `CI=true` 会开启 immutable 安装，而 setup 播种的空 lockfile 必须被填充，现在只为这一次安装关闭该开关。
- **原生冒烟测试适配 Windows**：窗口宽度断言容忍高 DPI 下的 1px 舍入，compact 断点改为读取 UI 的实际状态，原生菜单检查不再依赖 macOS 顶部应用菜单里的「退出」项，fixture 清理改为尽力而为。
- **Windows CI 现在会运行插件自己的测试套件**。此前的 Windows 作业只构建插件、从不运行它，这正是上述缺陷长期未被发现的原因。

## 项目窗口

- **恢复 Mica 材质选项**：自有 runtime 对象补上了官方的 `windowsBuild` 字段，设置页重新出现 Mica，材质也会写回项目 Home。
- **修复主题切换后左栏发黑**：浅色主题下切换主题会重涂窗口材质。

## 项目

- 打开项目时按项目定义自动重建缺失的资源目录。

## 验证与限制

- 两个仓库的 `yarn check` 全绿；macOS 上 7 个原生冒烟全部通过，Windows 侧由 `Verify Resources on Windows` 在 windows-2022 上验证。
- 本地原生验收基线仍为 macOS x64。安装包未签名（macOS 为 ad-hoc，Windows 未签名）。
