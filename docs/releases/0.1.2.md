DSH Project Desktop 0.1.2 — 复制修复版 / Clipboard copy fix

修复主界面消息复制按钮点击后没有反应的问题。Shell 曾给项目窗口与欢迎窗口的 Session 安装“全部拒绝”的 Web 权限处理器，`navigator.clipboard.writeText()` 也被一并拒绝并抛出 `NotAllowedError`；官方 DSH 客户端 UI 的 `writeClipboard` 会吞掉该异常且不显示失败反馈，因此按钮看起来完全失效。现在两个窗口只拒绝剪贴板以外的权限，保留 `clipboard-read` 与 `clipboard-sanitized-write`，其余行为不变。

This release fixes the message copy button doing nothing. The Shell installed a deny-everything Web permission handler on the project and welcome window Sessions, which also rejected `navigator.clipboard.writeText()` with `NotAllowedError`; the official DSH client `writeClipboard` swallows that rejection without any failure feedback, so the button appeared dead. Both windows now deny every permission except clipboard access, keeping `clipboard-read` and `clipboard-sanitized-write`; nothing else changes.

- 受影响入口：消息复制、代码块复制、终端块、表格、Read 块、HoverCard 与 JSON 树复制。
- 官方 Desktop runtime 自身不安装权限处理器，因此官方版复制可用；本次让 Shell 的裁剪策略与之一致。
- 项目窗口与欢迎窗口共用 `applyRendererPermissionPolicy`，并新增单元测试覆盖放行与拒绝清单。
- 未改动固定运行时：Desktop stable 2.0.11 / Harness 0.1.5-rc.2 与固定 Project 插件保持不变。

- Affected entry points: message copy, code block, terminal block, table, read block, hover card and JSON tree copy.
- The official Desktop runtime installs no permission handler, which is why copy works there; the Shell trimming policy now matches.
- The project and welcome windows share `applyRendererPermissionPolicy`, with a new unit test covering both the allowed and denied permission lists.
- Pinned runtimes are unchanged: Desktop stable 2.0.11 / Harness 0.1.5-rc.2 and the pinned Project plugin.

macOS 提供 Universal DMG（Intel / Apple Silicon），使用 ad-hoc 签名、未公证；Windows x64 提供未签名的 NSIS 安装程序和便携 ZIP。自动发布须通过两平台源码与原生检查、打包启动检查及同一 DMG 的 Intel 验收；Windows 安装向导、升级和卸载交互仍需人工验证。

macOS ships a Universal DMG (Intel / Apple Silicon), ad-hoc signed without notarization. Windows x64 ships unsigned NSIS and portable ZIP packages. Publication requires both platforms' source and native checks, packaged launch checks and Intel verification of the same DMG. Windows installer UI, upgrade and uninstall still require manual verification.
