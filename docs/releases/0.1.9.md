# 0.1.9 — 启动与打开项目耗时追踪、一键导出日志与诊断 / Startup and project-open timing, one-click logs-and-diagnostics export

## 中文

### 启动慢、打开项目慢，现在能直接看到卡在哪一段

此前只能靠离线探针或失败信息推测：实机启动/打开变慢时壳没有任何分阶段计时，Host 内部（首次 Profile 准备的 pnpm 依赖实体化、官方插件树）对主进程完全不可见。本版加入常开的分阶段追踪：

- **每次启动都写** `<userData>/boot.log`，不需要事先打开任何开关——慢往往发生在没开开关的那一次。`boot` 段是一次启动（从 Electron 主进程入口到欢迎窗口/首个项目窗口出现），`project/open:<项目>` 段是打开一个项目（解析项目文件 → Host 监督 → 分阶段启动 → 建窗 → 渲染进程认证 → 页面加载与健康上报 → 启动检查点）。
- **每行给两个数**：相对该段开始的偏移，以及该阶段自身的耗时。单阶段 ≥1000 ms 直接标 `[SLOW >1000ms]`，段落结束输出 `total` 与最慢阶段。实测能读到 `official host booted 6433 ms`、`host boot rpc returned 6960 ms` 这类量级。
- **Host 内部也计入同一段**：监督进程把日志路径与会话标签经子进程环境传下去，Host 追加自己的阶段——包括首次运行才会执行的 pnpm 依赖实体化（官方材料化器给它 120 秒预算），因此不再只看到一个笼统的「boot RPC 花了 25 秒」。
- **恢复模式原因并入**：每次进入恢复助手的原因除了写项目状态目录的 `recovery-events.jsonl`，也记进该次追踪，导出时一并带走。
- **文件有界**：超过 256 KiB（`DSH_PROJECT_BOOT_LOG_BYTES` 可改）按半量截断，只保留最新记录；写入失败只静默丢弃，绝不成为启动失败的原因。`DSH_PROJECT_BOOT_LOG` 可指定别的文件（设为空字符串即关闭），`DSH_PROJECT_BOOT_TRACE=1` 同时把同样的行打到 stdout。

### 项目工具 → 导出日志与诊断…

原来的「导出项目诊断…」升级为一次导出：

- 写出一份报告，包含数据来源、本次启动与各项目打开追踪的全文、以及每个项目的恢复原因清单；
- 把项目自己的官方诊断包 `dsh-diagnostics-*.zip` 复制到**同一目录**并在文件管理器中定位。报告与压缩包并排放置而不是互相替换：日志要能直接用编辑器打开，压缩包则满足官方诊断格式。

遇到慢启动或慢打开时，导出这一个文件即可用于分析。

### 打开项目终端不再点了没反应（随本版发布）

Windows 项目窗口的菜单是壳自绘顶栏，而「项目工具 → 打开项目终端」此前调用官方终端契约时漏传了必需的 `spawn`：官方实现在启动进程处直接调用它，因此必然抛 `TypeError`；官方 dispatcher 不 await、自绘菜单只 `console.error`、自有 runtime 也没有官方那样的错误弹窗，表现为点击后完全没有反馈。现在：

- 启动终端所需参数在一处凑齐（`spawn` 与 `onLaunchError`），同步抛错与异步启动失败统一交给调用方，失败经官方文案与官方消息框弹出错误；
- 「编辑」菜单补上 Electron win32 默认快捷键（Ctrl+Z/Y/X/C/V/A，取值由探针从固定 Electron 读回）；「视图」菜单**不打印**实际不生效的 Ctrl+R 与缩放键，避免印出假承诺；
- 自绘标题栏接入官方 locale 服务，切换应用语言后标题栏文案跟随更新。

### 插件更新（pin 从 5193e81 提到 d45b54f）

- **缺失资源的克隆入口改为图标动作并说明原因**：尚未就绪的资源此前在 28px 图标动作行里放一个文字按钮，且没有说明目录为何缺失；现在改用官方下载图标，提示「尚未克隆到项目内。克隆会把仓库检出到项目内的目标目录。」，且按钮禁用时提示仍可读。

### 工程与验证

- 新增 `yarn probe:startup-trace`：真实启动一次 Electron 壳并打开项目，校验 `boot` 段、`project/open:<项目>` 段、Host 进程阶段与慢阶段标记是否都写入，证据落在 `.runtime/startup-trace-*/boot.log`。
- 新增 `tests/boot-log.test.mjs`（12 项），覆盖阶段耗时与偏移、慢阶段标记、成功/失败计时、保留策略截断、写入失败静默、禁用与重定向、Host 复用会话、导出报告渲染。

### 已知限制

- 安装包未签名：Windows 未签名，macOS 为 ad-hoc 签名；首次运行可能触发 SmartScreen。
- 本版**没有升级官方运行时**：仍固定 DSH Harness `0.1.5-rc.2`（不是 0.1.5 正式版）与 Desktop `2.0.11`。
- 分阶段追踪的数值来自本地实机验证（Windows x64）；macOS 与 Linux 未逐平台复测，但代码路径相同。
- 追踪为纯文本且有界保留：它记录阶段与耗时，不采集会话内容、项目内容或凭据。

## English

### A slow launch or a slow project open now says which stage took the time

Until now the only options were offline probes or guessing from a failure message: a slow launch on a real machine had no staged timing at all, and the expensive part of a project open — the first Profile preparation's pnpm materialization and the official plugin tree — was invisible to the main process. This release adds an always-on staged trace:

- **Every launch writes** `<userData>/boot.log`, with no switch to remember first — slowness tends to happen on the launch where nobody turned tracing on. The `boot` trace covers one launch (from the Electron main-process entry to the welcome window or first project window), and `project/open:<project>` covers one open (project file resolution → Host supervision → staged boot → window creation → renderer authentication → page load and health report → startup checkpoint).
- **Every line carries two numbers**: the offset since that trace began and the stage's own cost. A stage of 1000 ms or more is marked `[SLOW >1000ms]`, and each trace ends with `total` and its slowest stage. Real runs read out as `official host booted 6433 ms`, `host boot rpc returned 6960 ms`.
- **The Host's own stages join the same trace**: the supervisor passes the log path and session label down through the child environment, so the Host appends its stages — including the pnpm dependency materialization that only a first run performs (the pinned official materializer allows it 120 seconds). No more a single opaque "the boot RPC took 25 seconds".
- **Recovery reasons are included**: every reason Recovery Mode opened is still written to the project's `recovery-events.jsonl`, and is now also recorded in that trace so the export carries it.
- **The file is bounded**: past 256 KiB (`DSH_PROJECT_BOOT_LOG_BYTES` changes it) it is truncated to its newest half, and a failed write is silently dropped so tracing can never become the reason a launch fails. `DSH_PROJECT_BOOT_LOG` points the trace at another file (empty string turns it off) and `DSH_PROJECT_BOOT_TRACE=1` also prints the same lines to stdout.

### Project Tools → Export Logs and Diagnostics…

The former "Export Project Diagnostics…" became one export:

- it writes a report with the data sources, the full text of this launch's and each project's open trace, and every project's recovery reasons;
- it copies the project's own official diagnostics archive `dsh-diagnostics-*.zip` into the **same folder** and reveals it. Report and archive sit side by side rather than replacing each other: a log has to open in a text editor, while the archive satisfies the official diagnostics format.

When a launch or an open is slow, that one file is what to send.

### Project terminal no longer does nothing when clicked (included in this release)

Windows project windows use the Shell's self-drawn titlebar, and "Project Tools → Open Project Terminal" called the official terminal contract without its required `spawn`: the official implementation calls it directly when starting the process, so it necessarily threw a `TypeError`; the official dispatcher does not await, the self-drawn menu only logged to `console.error`, and our runtime had none of the official error dialogs — so a click produced no feedback at all. Now:

- the launch options are assembled in one place (`spawn` and `onLaunchError`), synchronous throws and asynchronous launch failures both reach a reporter, and a failure shows the official copy in the official message box;
- the Edit menu carries Electron's win32 default accelerators (Ctrl+Z/Y/X/C/V/A, read back from the pinned Electron by a probe); the View menu deliberately does **not** print Ctrl+R or the zoom chords, which do not fire in this window shape;
- the self-drawn titlebar reads the official locale service, so its labels follow an application language switch.

### Plugin update (pin moved from 5193e81 to d45b54f)

- **Cloning a missing resource is now an icon action that states the reason**: a resource that was not ready yet used to render one text button among 28px icon actions, saying nothing about why the directory was missing. It now uses the official download glyph with the tooltip "Not in this project yet. Cloning checks the repository out into the project directory.", which stays readable while the action is disabled.

### Engineering and validation

- New `yarn probe:startup-trace`: one real Electron launch and project open that verifies the `boot` trace, a `project/open:<project>` trace, the Host-process stages and a slow-stage marker were all written, with evidence under `.runtime/startup-trace-*/boot.log`.
- New `tests/boot-log.test.mjs` (12 cases) covering stage cost and offset, the slow marker, success and failure timing, retention truncation, silent write failure, disabling and redirection, the Host continuing a session, and export report rendering.

### Known limitations

- Packages are unsigned: Windows unsigned, macOS ad-hoc signed; the first run may trigger SmartScreen.
- This release **does not upgrade the official runtime**: it still pins DSH Harness `0.1.5-rc.2` (not the 0.1.5 final release) and Desktop `2.0.11`.
- The staged numbers come from on-device verification on Windows x64; macOS and Linux were not re-measured per platform, though the code path is shared.
- The trace is bounded plain text: it records stages and durations, never session content, project content or credentials.
