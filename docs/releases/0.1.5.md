# DSH Project Desktop 0.1.5 — 项目资产审阅版 / Project asset review

本次发布的重点是让项目根仓库按「项目资产」而不是按文件来提交，并收敛启动超时预算。

This release focuses on committing the project root by **project asset** instead of by file, and on tightening the startup timeout budget.

## 中文

### 项目资产审阅

- **概览页新增「项目资产」区块**：项目根仓库的变更按任务、技能、记忆、MCP 与其他文件分组展示。一张卡片就是一个资产——任务是整个 `tasks/<目录>`（含全部附件）、技能是整个技能目录、MCP 是一条服务声明、记忆是一份文档；卡片标出新增/更新/删除，并显示该资产包含的文件数与产物数。
- **逐资产提交**：多选时每个资产各自生成一次提交，只包含它自己的路径，提交信息按类型自动生成（`feat(task): 收录「…」`、`feat(skills): 新增技能 …` 等）。把鼠标移到提交按钮上可以先看到这次会写入哪些提交；等待 Host 期间按钮显示进行中状态。
- **仓库状态即入口**：标题行的分支与同步状态本身就是按钮，点开「仓库详情」可检查更新、推送提交、切换分支与查看远端。概览打开时会自动检查一次，且不会锁住界面操作。
- **勾选不会被刷新打断**：项目打开期间任何工作树变动（技能服务改写索引、Agent 写入文件）都会刷新变更快照；现在只保留仍然存在的资产的选择，仅对本次新出现的资产套用默认勾选，不再清空用户已做的选择。
- **中文路径不再乱码**：Git 对非 ASCII 路径会做 C-quoting，此前中文任务目录会显示成八进制转义、并被错归到「其他文件」；现在路径按原文解析并归入正确的资产。

### 启动与超时

- 把 Host boot 的超时预算从 300 秒收敛到 120 秒：Windows CI 实测 boot 为 5.5–7.1 秒（4 vCPU runner），macOS arm64 为 2.5–3.0 秒，120 秒仍有 17 倍以上余量，真卡死时不必白等五分钟。
- 新增启动耗时探针与 `probe-boot-timing` 工作流，在真实 Windows runner 上分阶段测量源码构建与便携版的启动耗时，结果写入 step summary 与 artifact。

### 验证与限制

- 两个仓库的 `yarn check` 全绿；插件测试套件 270 条。
- macOS 上的原生冒烟覆盖中英文、明暗主题、1180/420 两种宽度、键盘操作，以及一次真实的多资产提交（每个资产各一个提交、只含自身路径），并断言刷新快照不会重新勾选用户已清空的资产。
- 已知限制：MCP 的多个服务共享 `mcp/servers.yaml`，不能逐个服务提交；「其他文件」默认不勾选；项目记忆仍没有新增入口。
- 安装包未签名（macOS 为 ad-hoc，Windows 未签名）。

## English

### Project asset review

- **New "Project assets" section on the project overview**: changes in the project-root repository are grouped as tasks, Skills, memory documents, MCP declarations and other files. One card is one asset — a task is the whole `tasks/<directory>` (attachments included), a Skill is its whole directory, an MCP entry is one server declaration and a memory entry is one document. Each card is labelled added/updated/deleted and shows how many files and artifacts it covers.
- **One commit per asset**: selecting several assets produces one commit each, containing only that asset's own paths, with a message derived from its type (`feat(task): …`, `feat(skills): …`). Hovering the submit button previews exactly which commits will be written, and the button reports progress while the Host works.
- **The repository state is the entry point**: the branch and sync state in the section title are a button that opens "Repository details", where checking for updates, pushing, switching branches and inspecting the remote live. The overview checks once when it opens, without locking the rest of the interface.
- **Selections survive snapshot refreshes**: any worktree change while the project is open (a Skill index rewrite, a file the Agent writes) refreshes the change snapshot. The panel now keeps the selection of assets that still exist and only default-selects assets that newly appeared, instead of discarding what the user already ticked.
- **Non-ASCII paths are decoded**: Git C-quotes non-ASCII paths, which previously showed Chinese task directories as octal escapes and misfiled them under "Other files". Paths are now read literally and grouped into the right asset.

### Startup and timeouts

- The Host boot timeout budget is tightened from 300 s to 120 s: Windows CI measures 5.5–7.1 s (4 vCPU runner) and macOS arm64 2.5–3.0 s, leaving more than a 17× margin while avoiding a five-minute wait on a genuine hang.
- New boot-timing probes and a `probe-boot-timing` workflow measure source-build and packaged startup in stages on a real Windows runner, writing results to the step summary and an artifact.

### Verification and limitations

- `yarn check` is green in both repositories; the plugin suite has 270 tests.
- Native smoke on macOS covers English and Chinese, light and dark themes, 1180/420 widths, keyboard operation and one real multi-asset commit (one commit per asset, each containing only its own paths), and asserts that refreshing the snapshot does not re-tick assets the user cleared.
- Known limitations: several MCP servers share `mcp/servers.yaml`, so they cannot be committed one server at a time; "Other files" are not selected by default; project memory still has no creation path.
- Installers are unsigned (ad-hoc on macOS, unsigned on Windows).
