# 0.1.10 — 修复导出入口回归、导出留痕，Host 启动拆到子阶段 / Export entry regression fix, export trace, Host boot sub-stages

## 中文

### 修复 0.1.9 的导出入口回归（建议升级）

0.1.9 把项目 runtime 的官方方法 `exportDiagnostics` 改名成了 `exportLogs`，而固定 Host 的 `bindNativeRuntime` 是按名字分发 `native:exportDiagnostics` 的：项目工具菜单里官方插件贡献的「导出诊断信息…」一点就抛 `TypeError: Cannot read properties of undefined (reading 'apply')`，并弹出原生错误框。同时它与壳自己的「导出日志与诊断…」并列，两个入口把同一份证据写到两处。

现在：

- **恢复官方方法名 `exportDiagnostics`**（行为仍是合并导出：报告 + 官方诊断 zip 写到同一目录）；
- **项目工具菜单只保留「导出日志与诊断…」一个导出入口**：官方 `desktop-diagnostics` 的重复条目在 group、order 与官方文案三者同时匹配时才丢弃，任一不符即保留，避免误删未知命令；
- 新增 `tests/desktop-runtime-contract.test.mjs`：从固定 `host-runtime-bridge.ts` 提取 `native:<method>` 列表并逐个断言壳 runtime 实现——这次回归从此是机械失败，而不是用户机器上的报错。

### 每次导出留下自己的追踪段

此前导出会往已经结束的 `boot` 段写 `logs exported`，而追踪结束时会置 `finished`、之后的事件被静默忽略，`boot.log` 里看不出导出有没有发生、成功还是失败。现在每次导出另开一段 `export` 追踪，记录目标路径、字节数、诊断包路径与总耗时；失败的导出同样留下记录。报告里的说明段也补上了 export 段的解释。

### Host 启动拆成子阶段，并指出最慢的插件入口

打开项目最贵的一段在 Host 进程内：官方 `boot()` 同时盖住 Loader 装载、整棵插件树与 loopback 渲染服务器，此前只有一个 `official host booted` 数字——Windows 实机的 28 s 与 macOS 本机的 3 s 在追踪里读起来完全一样。现在：

- `official host booted` 之前补出 `official host modules resolved`、`official host log sink ready`、`official loader mounted`、`official runtime services provided`、`official actions service mounted`、`official cmdline provided`；
- 监听 Loader 的 `internal/status`，在 `official host booted` 之后写 `official plugin tree settled`（已装载入口数、失败数、最慢入口），并对 ≥1000 ms 的入口另写一行 `official plugin loads over 1000ms`；汇总放在该阶段之后，以免改变 `official host booted` 一直报告的等待量；
- `yarn probe:startup-trace` 增加 `host boot sub-stages` 检查，两个新阶段缺失即失败。

实测（macOS arm64）：`official host booted 2973 ms` 之下 `loaded=180`、`slowest=cordis:include 2957 ms`、`dsh-plugin-desktop/webserver 2056 ms`。

### 插件更新（pin 从 d45b54f 提到 4633866）

- **资源卡片「本地领先 n 个提交」的悬停不再重复计数**：标签本身已经写着数量，气泡再重复一遍是冗余；现在领先状态下气泡只逐行列出领先的提交（超过 20 条以「另有 n 个本地提交」收尾），其他状态仍保持「标签 · 说明」。卡片上的橙色标签不变。
- 壳侧的原生断言随之改为严格等于「<短 hash> <标题>」——相等同时证明提交被列出、且标签的计数行没有被重复。

### 工程与验证

- **macOS 上 `yarn probe:startup-trace` 不再必然 exit 1**：标题栏语言检查此前直接对 darwin 上返回 `null` 的 `readTitlebarLocale()` 取 `.menus`，整条原生冒烟在标题栏检查处抛错（其 7 项追踪检查其实都通过）。该检查已收进 `checkTitlebarLocale()` 并按平台跳过，macOS 上原生冒烟现在能完整跑完。
- 验证：`yarn check` EXIT=0；`yarn probe:startup-trace` 8/8 且原生冒烟退出码 0；真实 Electron 端到端（真实菜单点击 → 同目录报告 + 官方诊断 zip、菜单只有一个导出入口）通过。

### 已知限制

- 安装包未签名：Windows 未签名，macOS 为 ad-hoc 签名；首次运行可能触发 SmartScreen。
- 本版**没有升级官方运行时**：仍固定 DSH Harness `0.1.5-rc.2` 与 Desktop `2.0.11`。
- 分阶段追踪的数值来自本地实机验证（Windows x64 与 macOS arm64 各覆盖一部分）；Linux 未逐平台复测。
- 追踪为纯文本且有界保留：它记录阶段与耗时，不采集会话内容、项目内容或凭据。

## English

### Fixed the 0.1.9 export-entry regression (upgrade recommended)

0.1.9 renamed the project runtime's official `exportDiagnostics` method to `exportLogs`. The pinned Host dispatches `native:exportDiagnostics` by name through `bindNativeRuntime`, so the official "Export Diagnostics…" entry in Project Tools failed with `TypeError: Cannot read properties of undefined (reading 'apply')` behind a native error dialog — and it sat beside the Shell's own "Export Logs and Diagnostics…" entry, sending the same evidence to two places.

Now:

- **The official method name `exportDiagnostics` is restored** (the behaviour is still the merged export: report and official diagnostics zip written into one folder);
- **Project Tools keeps exactly one export entry, "Export Logs and Diagnostics…"**: the official `desktop-diagnostics` duplicate is dropped only when group, order and the official label all agree; anything that does not match every one of them stays visible, so an unknown command is never removed by accident;
- `tests/desktop-runtime-contract.test.mjs` extracts the `native:<method>` list from the pinned `host-runtime-bridge.ts` and asserts the Shell runtime implements each one — this regression is now a mechanical failure instead of an error on someone's machine.

### Every export leaves its own trace section

An export used to append `logs exported` to the already-finished `boot` trace; the trace marks itself finished when it ends, so the event was silently dropped and `boot.log` could not tell whether an export happened, succeeded or failed. Each export now opens its own `export` section recording the destination, byte count, archive path and total cost; a failed export is recorded too. The report's notes section explains the new section.

### Host boot split into sub-stages, naming the slowest plugin entry

The most expensive part of a project open happens inside the Host: the official `boot()` covers Loader mounting, the whole plugin tree and the loopback renderer server at once, so the trace showed a single `official host booted` number — a 28 s Windows run and a 3 s macOS run read exactly the same. Now:

- `official host modules resolved`, `official host log sink ready`, `official loader mounted`, `official runtime services provided`, `official actions service mounted` and `official cmdline provided` are recorded before `official host booted`;
- the Loader's `internal/status` is observed to write `official plugin tree settled` after `official host booted` (entries loaded, failures, slowest entry), plus one `official plugin loads over 1000ms` line per entry at or above 1000 ms; the summary lands after that stage so the wait `official host booted` has always reported does not change;
- `yarn probe:startup-trace` gained a `host boot sub-stages` check that fails when the two new stages are missing.

Measured (macOS arm64): under `official host booted 2973 ms`, `loaded=180`, `slowest=cordis:include 2957 ms`, `dsh-plugin-desktop/webserver 2056 ms`.

### Plugin update (pin moved from d45b54f to 4633866)

- **The resource card's "N local commits ahead" hover no longer repeats the count**: the tag already states the number, so the bubble now lists the commits themselves, one per line (past 20 it ends with "{count} more local commits"); every other state keeps the previous "label · explanation" text. The orange tag on the card is unchanged.
- The Shell's native assertion now requires exact equality with "<short hash> <title>", which proves both that the commit is named and that the tag's count line is not repeated.

### Engineering and verification

- **`yarn probe:startup-trace` no longer always exits 1 on macOS**: the titlebar locale check dereferenced `readTitlebarLocale()`, which returns `null` on darwin, so the whole native smoke threw at the titlebar check even though its seven trace checks passed. That check moved into `checkTitlebarLocale()` behind the platform guard, and the native smoke now runs to completion on macOS.
- Verification: `yarn check` EXIT=0; `yarn probe:startup-trace` 8/8 with native smoke exit code 0; a real Electron end-to-end run (real menu click → report + official diagnostics zip in one folder, one export entry in the menu) passed.

### Known limitations

- The installers are unsigned: Windows is unsigned and macOS is ad-hoc signed; the first launch may trigger SmartScreen.
- **The official runtime was not upgraded**: still pinned to DSH Harness `0.1.5-rc.2` and Desktop `2.0.11`.
- The staged-trace numbers come from local real-machine runs (Windows x64 and macOS arm64, each covering part of the path); Linux was not re-tested per platform.
- The trace is plain text with bounded retention: it records stages and durations, not session content, project content or credentials.
