# 0.1.8 — 关于面板显示 DSH 运行时版本、欢迎窗口克隆导入与目录记忆 / About panel shows the DSH runtime version, repository import and directory memory

## 中文

### 关于面板现在显示正在运行的 DSH 版本

macOS 应用菜单的「关于 DSH Project Desktop」与 Windows/Linux 自绘顶栏「项目工具 → 关于 DSH Project Desktop」现在是同一个原生面板
（`app.setAboutPanelOptions` 统一配置，顶栏入口经 Shell titlebar action `about` 调用 `app.showAboutPanel()`）：

```
DSH Project Desktop
版本 0.1.8（DSH 0.1.5-rc.2）
```

- **DSH 版本与壳版本同处一行、同一字号**：macOS 面板把该值渲染在版本行的括号里，因此不需要额外的小字行。
- Windows/Linux 的面板没有构建号字段，改由 credits 行输出 `DSH (DeepSeek Harness) 0.1.5-rc.2`。
- 数值取自带稳定锁的 Harness 版本，而 Host 启动时会校验实际安装版本与锁一致，所以面板显示的就是真实运行版本，不是写死的文案。
- Windows 此前没有任何「关于」入口（原生菜单栏在该窗口形态下不可见），本版在顶栏「项目工具」末尾补上。

### 欢迎窗口：打开文件夹探测、从 Git 仓库克隆导入、记住上次目录

- **打开**：原生选择器现在同时允许文件和文件夹。选中文件夹时由壳探测根目录唯一的 `*.agent-project`：没有项目文件用欢迎窗口自己的中英文案提示，多个项目文件不静默选择。Windows/Linux 无法双选，退化为文件夹选择，并在多项目目录时补一次只选文件的对话框；菜单与顶栏的「打开项目…」走同一套判定。
- **克隆仓库**：欢迎窗口新增入口（工具栏顺序：克隆仓库 / 新建项目 / 打开）。校验地址、分支、文件夹名与目标是否已存在后，复用创建向导的克隆机制（私有仓库沿用既有凭据链），弹窗显示路径预览与真实克隆阶段/百分比。克隆完成后只接受根目录恰好一个 `*.agent-project`：通过则直接打开；没有项目文件时删除刚克隆的内容；有多个时保留克隆内容并在提示中给出路径——删掉用户仍可手动打开的检出属于数据丢失，所以不做。
- **目录记忆**：统一到 `src/app/last-directories.mjs`，导入弹窗用 `import` 键，资源、资源重定位与技能导入共用 `resource` 键。上次目录只是选择器的起始位置，只有用户真正选了才覆盖，取消不动，记录里的目录已不存在时不再使用。

### Git 系统代理注入不再覆盖操作者环境

- `no_proxy` / `NO_PROXY` 改为「产品默认排除项 + 继承环境既有排除项」的合并，按大小写去重并保留操作者拼写。
- 操作者已导出 `http_proxy` / `https_proxy`（任一大小写）时不再注入解析出的代理地址，只强制补全排除列表，避免 loopback 与产品自有 fixture 经过代理。
- 默认排除列表补齐整个 `127.0.0.0/8` 与 `[::1]`；Host 启动日志如实区分「注入解析结果」与「沿用继承环境」。

### 插件更新（pin 从 e28b0ed 提到 5193e81）

- **资源卡片悬停显示领先的本地提交**：同步标签不再只显示计数，悬停按「标签行 + 每条提交一行」列出领先提交（新→旧，最多 20 条，hash + 标题），超出上限以「另有 n 个本地提交」收尾；读取提交列表失败只丢列表，不会把同步状态变成错误。
- **插件滚动区滚动条空闲淡出**：12 个插件滚动容器由同一清单登记，空闲 800ms 后透明、滚动立即显示、停止 180ms 淡出、拖动滑块保持可见、减少动态效果直接切换；不改变 overflow、稳定槽与内容宽度。
- **技能索引变更随技能提交**：修复 `skills/index.yaml` 的变更永远提交不上去的问题（兜底资产按技能名重建索引会把 HEAD 内容原样写回，提交以 `nothing to commit` 失败）。索引变更现在按 HEAD 与工作区的显式条目差异归属到 `skill:<name>`；关闭再启用后索引回到 HEAD，不再留下 `enabled: true` 残留 diff。

### 工程与验证

- 新增原生验收脚本：插件滚动条空闲淡出探针、资源卡片悬停领先提交检查；`smoke:resources` 补回目录记忆断言。
- 项目新增《多会话并发写入约束》设计文档（C1–C8 约束与强制点）。

### 已知限制

- **Windows/Linux 顶栏新增的「关于」入口本版没有实机视觉验收**：只有单元测试与代码路径验证。macOS 原生面板已在开发壳上核实（见下）。
- macOS 关于面板的验收方式：开发壳（隔离 userData）+ 主进程 inspector 触发 `app.showAboutPanel()`，对该面板窗口截图后用 macOS Vision OCR 读取文本，得到 `DSH Project Desktop / 版本 0.1.8（DSH 0.1.5-rc.2）`。OCR 只证明文本与渲染行，不证明视觉效果的全部细节。
- 欢迎窗口的目录记忆与克隆导入在 Windows 上的实机结论见项目任务 `task-7af5d595`（另一份记录，不在本发布说明内）。
- 本版**没有升级官方运行时**：仍固定 DSH Harness `0.1.5-rc.2`（不是 0.1.5 正式版）与 Desktop `2.0.11`。
- 安装包未签名：Windows 未签名，macOS 为 ad-hoc 签名。
- 发布备注：`v0.1.8` 这个 tag 曾被一次被取消的构建占用（那次没有产出 Release），本次沿用该版本号，tag 已指向本次发布提交。

## English

### The About panel now shows the running DSH version

The macOS application menu's "About DSH Project Desktop" and the Windows/Linux self-drawn titlebar entry
("Project Tools → About DSH Project Desktop") are now the same native panel (configured once through
`app.setAboutPanelOptions`; the titlebar entry reaches it via the Shell titlebar action `about` and
`app.showAboutPanel()`):

```
DSH Project Desktop
版本 0.1.8（DSH 0.1.5-rc.2）
```

- **The DSH version sits on the shell version's own line, at the same type size**: the macOS panel renders
  it inside that line's parentheses, so no extra small-print row is needed.
- The Windows/Linux panel has no build field, so it prints `DSH (DeepSeek Harness) 0.1.5-rc.2` on its credits line.
- The value comes from the stable lock's Harness version, and the Host refuses to start when the installed
  version differs from the lock — so the panel shows the real running version instead of a hard-coded string.
- Windows had no About entry at all (the native menu bar cannot show in this window shape); this release adds
  one at the end of the titlebar's Project Tools menu.

### Welcome window: folder probing on Open, clone-from-repository import, remembered directories

- **Open**: the native picker now accepts files and folders. When a folder is chosen the Shell probes for the
  single `*.agent-project` at its root: no project file produces the welcome window's own localized message,
  several project files are never silently resolved. Windows/Linux cannot select both, so they fall back to
  folder selection and add a files-only dialog when the folder is ambiguous; the menu and titlebar
  "Open Project…" share the same decision.
- **Clone Repository**: a new welcome-window entry (toolbar order: Clone / New Project / Open). After validating
  the URL, branch, folder name and whether the target exists, it reuses the creation guide's clone machinery
  (private remotes keep the existing credential chain), and the dialog shows a path preview plus the real clone
  phase and percentage. A finished clone is accepted only when the root holds exactly one `*.agent-project`:
  it opens directly; with no project file the freshly cloned content is removed; with several, the checkout is
  kept and its path is reported — deleting a checkout the user could still open by hand would be data loss.
- **Remembered directories**: unified in `src/app/last-directories.mjs` — the import dialog uses the `import`
  key, while resources, resource relocation and skill import share the `resource` key. The remembered folder is
  only the picker's starting point, it is replaced only after a real selection, cancelling changes nothing, and
  a folder that no longer exists is not offered again.

### Git's system-proxy injection no longer overrides the operator's environment

- `no_proxy` / `NO_PROXY` are now the merge of the product's defaults and the inherited exclusions, deduplicated
  case-insensitively while keeping the operator's spelling.
- When the operator already exported `http_proxy` / `https_proxy` (either case), the resolved address is not
  injected at all: only the exclusion list is enforced, so loopback and the product's own fixtures never travel
  through a proxy the operator did not exclude.
- The default exclusions now cover the whole `127.0.0.0/8` block and `[::1]`, and the Host start-up log
  distinguishes "injected the resolved proxy" from "kept the inherited environment".

### Plugin update (pin moved from e28b0ed to 5193e81)

- **Resource cards show leading local commits on hover**: the sync label no longer shows only a count. Hovering
  lists the leading commits (newest first, up to 20, hash + subject) under the label line and ends with
  "n more local commits"; failing to read the list drops only the list, never turning the sync state into an error.
- **Plugin scrollbars fade out when idle**: twelve plugin scroll containers are registered in one list — idle for
  800ms fades them out, scrolling shows them immediately, stopping fades over 180ms, dragging the thumb keeps
  them visible, and reduced motion switches instantly. Overflow, stable gutters and content width are unchanged.
- **Skill index changes are committed with the skill**: fixes changes to `skills/index.yaml` never being
  committable (the fallback asset rebuilt the index from the skill name, writing HEAD's content back and failing
  with `nothing to commit`). Index changes are now attributed to `skill:<name>` from the explicit-entry diff
  between HEAD and the worktree, and disabling then re-enabling a skill returns the index to HEAD instead of
  leaving an `enabled: true` residue.

### Engineering and validation

- New native acceptance scripts: an idle-scrollbar probe for the plugin, and leading-commit hover checks for
  resource cards; `smoke:resources` regained its directory-memory assertions.
- A session write-concurrency design document (C1–C8 constraints and their enforcement points) was added.

### Known limitations

- **The new Windows/Linux titlebar About entry has no on-device visual acceptance in this release**: only unit
  tests and the code path were verified. The macOS native panel was verified on the development shell (below).
- How the macOS panel was verified: a development shell with an isolated userData directory, the main-process
  inspector triggering `app.showAboutPanel()`, then a screenshot of that panel window read back with macOS
  Vision OCR, yielding `DSH Project Desktop / 版本 0.1.8（DSH 0.1.5-rc.2）`. OCR proves the text and the rendered
  line, not every visual detail.
- Windows on-device conclusions for directory memory and clone import are recorded in project task
  `task-7af5d595` (a separate record, not part of these notes).
- This release **does not upgrade the official runtime**: it still pins DSH Harness `0.1.5-rc.2` (not the 0.1.5
  final release) and Desktop `2.0.11`.
- Packages are unsigned: Windows unsigned, macOS ad-hoc signed.
- Release note: the `v0.1.8` tag had been left behind by a cancelled build (which produced no Release); this
  release reuses that version number and the tag now points at this release's commit.
