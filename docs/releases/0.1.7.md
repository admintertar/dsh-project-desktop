# 0.1.7 — Windows 顶栏菜单 / Windows titlebar menu

## 中文

### Windows：项目窗口有了可见的菜单入口

Windows 上项目窗口使用「隐藏标题栏 + 系统窗口按钮覆盖层」（`titleBarStyle: 'hidden'` + `titleBarOverlay` + `autoHideMenuBar`）。
实机实测该形态下**原生菜单栏根本无法显示**：`isMenuBarVisible()` 恒为 false，外部 Win32 查询 `GetMenu(hwnd) == 0`，
左 Alt / F10 / 右 Alt / `setMenuBarVisibility(true)` / `setAutoHideMenuBar(false)` / `setMenu(appMenu)` 全部无效
（对照：标准系统边框窗口可以正常显示 26 DIP 的菜单栏）。

结果是「新建项目 / 打开项目 / 最近项目」此前在 Windows 上没有任何可见入口，只剩不可发现的快捷键。
本版在窗口顶栏自绘了一条菜单：

- 左侧：收起/展开侧栏按钮、当前项目名（宽度跟随侧栏列宽实时变化，过长截断，不会越过可拖动的侧栏边界）
- 其后：**文件**（新建项目… `Ctrl+Shift+N`、打开项目… `Ctrl+O`、欢迎窗口、关闭项目 `Ctrl+W`、最近项目列表）、
  **编辑**（撤销/重做/剪切/复制/粘贴/全选）、**视图**（重新加载、切换开发者工具、实际大小/放大/缩小、切换全屏）、
  **项目工具**（打开项目终端、导出项目诊断…、Profile…、重启当前项目、在安全模式中打开、项目恢复…、检查更新…）
- 顶栏填充跟随**窗口材质**：Mica / 透明时使用半透明洗色，材质关闭时使用表层色（与官方整条顶栏同一规则）
- 收起侧栏时，左侧完全保持官方 rail 外观；侧栏分界线不再延伸进顶栏

### Windows：快捷键不再依赖全局应用菜单

`Ctrl+Shift+N` / `Ctrl+O` / `Ctrl+W` 改为**窗口级绑定**（`before-input-event`）。
这既让它们在菜单栏不可见的窗口里继续有效，也为后续对齐官方 Windows 策略
（建窗后 `removeMenu()`，实测会让菜单加速键全部失效）留出空间。macOS 不安装该层，保持系统菜单栏语义。

### 实现边界

顶栏通过官方 client slot（`shell.overlay`）注入，几何取自官方 `desktopWindow.dragRegion`，
收起侧栏调用官方 `layout.toggleSidebar()`；命令走官方渲染进程桥。**固定的官方源码快照未做任何修改。**

### 已知限制

- macOS 行为未改动（顶栏只在 Windows/Linux 注册），但本轮没有 macOS 实机回归。
- 插件贡献的「项目工具」条目尚未进顶栏菜单的动态分组。
- 安装包未签名：Windows 未签名，macOS 为 ad-hoc 签名。

## English

### Windows: the project window finally has visible menu entries

Project windows on Windows use a hidden title bar with the system window-controls overlay
(`titleBarStyle: 'hidden'` + `titleBarOverlay` + `autoHideMenuBar`). Measured on a real machine,
that window shape **cannot display a native menu bar at all**: `isMenuBarVisible()` is always false,
an external Win32 query returns `GetMenu(hwnd) == 0`, and Left Alt / F10 / Right Alt /
`setMenuBarVisibility(true)` / `setAutoHideMenuBar(false)` / `setMenu(appMenu)` all do nothing
(a standard-framed control window does show its 26 DIP menu bar).

As a result, "New Project / Open Project / Recent Projects" had no visible entry point on Windows —
only undiscoverable accelerators. This release draws a menu into the titlebar itself:

- Left: collapse/expand sidebar, current project name (its width follows the live sidebar column,
  truncates when long, and never crosses the draggable sidebar boundary)
- Then: **File** (New Project… `Ctrl+Shift+N`, Open Project… `Ctrl+O`, Welcome Window, Close Project `Ctrl+W`,
  Recent Projects), **Edit**, **View** (Reload, Toggle Developer Tools, Actual Size / Zoom In / Zoom Out,
  Toggle Full Screen) and **Project Tools** (Open Project Terminal, Export Project Diagnostics…, Profiles…,
  Restart Current Project, Open in Safe Mode, Project Recovery…, Check for Updates…)
- The titlebar fill follows the **window material**: a translucent wash over Mica/transparent,
  the surface colour when material is off (the same rule the official frame titlebar uses)
- When the sidebar is collapsed the left side keeps the official rail untouched, and the sidebar
  divider no longer runs through the titlebar

### Windows: shortcuts no longer depend on the global application menu

`Ctrl+Shift+N` / `Ctrl+O` / `Ctrl+W` are now bound per window (`before-input-event`). That keeps them
working in a window that shows no menu bar, and leaves room for aligning with the official Windows
strategy (`removeMenu()` after window creation, which was measured to kill every menu accelerator).
macOS does not install this layer and keeps its system menu bar semantics.

### Implementation boundary

The titlebar is injected through the official client slot (`shell.overlay`), takes its geometry from the
official `desktopWindow.dragRegion`, calls the official `layout.toggleSidebar()` for the sidebar toggle,
and sends commands over the official renderer bridge. **The pinned official source tree is unmodified.**

### Known limitations

- macOS behaviour is unchanged (the titlebar only registers on Windows/Linux), but this round had no
  macOS machine to regress against.
- Plugin-contributed Project Tools entries are not yet rendered as a dynamic group in the titlebar menu.
- Packages are unsigned: Windows unsigned, macOS ad-hoc signed.
