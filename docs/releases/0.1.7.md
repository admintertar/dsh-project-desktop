# 0.1.7 — Windows 顶栏菜单、模态一致性与宽度修复 / Windows titlebar menu, modal consistency and width fixes

## 中文

### Windows：项目窗口有了可见的菜单入口

Windows 上项目窗口使用「隐藏标题栏 + 系统窗口按钮覆盖层」（`titleBarStyle: 'hidden'` + `titleBarOverlay` + `autoHideMenuBar`）。
实机实测该形态下**原生菜单栏根本无法显示**：`isMenuBarVisible()` 恒为 false，外部 Win32 查询 `GetMenu(hwnd) == 0`，
左 Alt / F10 / 右 Alt / `setMenuBarVisibility(true)` / `setAutoHideMenuBar(false)` / `setMenu(appMenu)` 全部无效
（对照：标准系统边框窗口可以正常显示 26 DIP 的菜单栏）。因此「新建项目 / 打开项目 / 最近项目」此前在 Windows 上
没有任何可见入口，只剩不可发现的快捷键。

修复：在官方 `shell.overlay` 里自绘一条满宽顶栏 ——

- 左侧：收起/展开侧栏按钮、当前项目名（宽度跟随侧栏列宽，过长截断，不越过可拖动的侧栏边界）
- 其后：**文件**（新建项目… `Ctrl+Shift+N`、打开项目… `Ctrl+O`、欢迎窗口、关闭项目 `Ctrl+W`、最近项目列表）、
  **编辑**、**视图**、**项目工具**（打开项目终端、导出项目诊断…、Profile…、重启当前项目、在安全模式中打开、项目恢复…、检查更新…）
- 顶栏填充跟随**窗口材质**（Mica / 透明时半透明，材质关闭时用表层色）
- 收起侧栏时左侧完全保持官方 rail 外观；侧栏分界线不再延伸进顶栏

### Windows：快捷键不再依赖全局应用菜单

`Ctrl+Shift+N` / `Ctrl+O` / `Ctrl+W` 改为**窗口级绑定**（`before-input-event`），在菜单栏不可见的窗口里继续有效，
也为后续对齐官方 Windows 策略（建窗后 `removeMenu()`，实测会让菜单加速键全部失效）留出空间。macOS 不安装该层。

### 模态一致性

打开设置或对话框时，官方遮罩层的层级**低于**官方 overlay（顶栏渲染在其中），导致顶栏既没有跟随虚化、
又浮在模态面板之上挡住其顶部。现在模态打开期间把 overlay 降到遮罩之下：顶栏保留并与整窗一起变暗，
设置面板完整可见——与主窗口自身的 chrome 行为一致。

### 项目名宽度跟随侧栏

早先的实现用 `getComputedStyle(frame).gridTemplateColumns` 加 `MutationObserver` 取值：窗口最大化时该属性不变，
而布局早期侧栏处于收起态（56px），这个值被当成上限后一直没被覆盖，于是**短项目名也会被提前截断**
（例如最大化时显示成 `modal2-p...`）。现在改为用 `ResizeObserver` 观察侧栏元素自身的实时宽度，
并忽略收起态的 rail 宽度（56px）：展开/最大化时上限随侧栏列宽变化，长名截断到侧栏边界，短名完整显示。

### 实现边界与已知限制

顶栏通过官方 client slot（`shell.overlay`）注入，几何取自官方 `desktopWindow.dragRegion`，
收起侧栏调用官方 `layout.toggleSidebar()`，命令走官方渲染进程桥；**固定的官方源码快照未做任何修改**。

- macOS 行为未改动（顶栏只在 Windows/Linux 注册），但本版没有 macOS 实机回归。
- 插件贡献的「项目工具」条目尚未作为动态分组渲染进顶栏菜单。
- 安装包未签名：Windows 未签名，macOS 为 ad-hoc 签名。

## English

### Windows: the project window finally has visible menu entries

Project windows on Windows use a hidden title bar with the system window-controls overlay
(`titleBarStyle: 'hidden'` + `titleBarOverlay` + `autoHideMenuBar`). Measured on a real machine, that
window shape **cannot display a native menu bar at all**: `isMenuBarVisible()` is always false, an
external Win32 query returns `GetMenu(hwnd) == 0`, and Left Alt / F10 / Right Alt /
`setMenuBarVisibility(true)` / `setAutoHideMenuBar(false)` / `setMenu(appMenu)` all do nothing
(a standard-framed control window does show its 26 DIP menu bar). "New Project / Open Project /
Recent Projects" therefore had no visible entry point on Windows — only undiscoverable accelerators.

Fix: a full-width titlebar row drawn into the official `shell.overlay` —

- Left: collapse/expand sidebar, current project name (its width follows the sidebar column,
  truncates when long, never crosses the draggable sidebar boundary)
- Then: **File** (New Project… `Ctrl+Shift+N`, Open Project… `Ctrl+O`, Welcome Window, Close Project `Ctrl+W`,
  Recent Projects), **Edit**, **View** and **Project Tools** (Open Project Terminal, Export Project
  Diagnostics…, Profiles…, Restart Current Project, Open in Safe Mode, Project Recovery…, Check for Updates…)
- The fill follows the **window material** (a translucent wash over Mica/transparent, the surface
  colour when material is off)
- When the sidebar is collapsed the left side keeps the official rail untouched, and the sidebar
  divider no longer runs through the titlebar

### Windows: shortcuts no longer depend on the global application menu

`Ctrl+Shift+N` / `Ctrl+O` / `Ctrl+W` are bound per window (`before-input-event`), so they keep working
in a window that shows no menu bar, and leave room for aligning with the official Windows strategy
(`removeMenu()` after window creation, measured to kill every menu accelerator). macOS installs nothing.

### Modal consistency

When a settings surface or dialog opened, the official scrim was painted BELOW the official overlay
that hosts the titlebar, so the bar neither dimmed with the window nor stopped covering the top of the
dialog. The overlay now drops beneath the scrim while a modal is open: the bar stays rendered and dims
together with the rest of the window, and the settings panel is fully visible — matching the main
window's own chrome.

### Project-name width follows the sidebar

The earlier implementation read `getComputedStyle(frame).gridTemplateColumns` through a
`MutationObserver`. That value does not change when the window is maximised, and while the layout
settles the sidebar is briefly the collapsed rail (56px); that stale value stuck as the cap, so even a
short project name was truncated (a maximised window showed `modal2-p...`). It now observes the sidebar
element's own live width with a `ResizeObserver` and ignores the collapsed rail width, so the cap
follows the column, long names truncate at the sidebar edge and short names render in full.

### Implementation boundary and known limitations

The titlebar is injected through the official client slot (`shell.overlay`), takes its geometry from the
official `desktopWindow.dragRegion`, calls the official `layout.toggleSidebar()` for the sidebar toggle,
and sends commands over the official renderer bridge. **The pinned official source tree is unmodified.**

- macOS behaviour is unchanged (the titlebar only registers on Windows/Linux); no macOS machine was
  available to regress against.
- Plugin-contributed Project Tools entries are not yet rendered as a dynamic group in the titlebar menu.
- Packages are unsigned: Windows unsigned, macOS ad-hoc signed.

### Git 命令继承本机系统代理

本机 `git` 直连 `github.com:443` 会超时（约 20 秒后失败），而同一时刻系统里其它程序走代理是正常的
（Windows 的系统代理设置在部分程序里并不自动生效）。现在壳在打开项目时检测本机系统代理，
并把可用的代理以环境变量形式注入项目 Host，使插件发起的 clone / fetch / push 与 Git LFS 都经由该代理；
检测不到可用代理时保持直连，不额外增加 Git 超时。

### Git inherits the machine's system proxy

On this machine `git` cannot reach `github.com:443` directly (it fails after roughly 20 seconds) even though
other programs reach it through the system proxy — Windows proxy settings are not picked up by every program.
The shell now detects the machine's system proxy while opening a project and injects it into the project Host
as environment variables, so clones, fetches, pushes and Git LFS performed by the plugin go through that proxy.
When no usable proxy is detected it stays direct, without adding extra Git timeouts.
### 插件修复：资产提交失败只报一次

项目资产提交失败时，错误提示现在只出现一次（此前在文件列表之后会重复提示同一条错误）。

### Plugin fix: asset-commit failures are reported once

When committing project assets fails, the error is now shown once instead of being repeated after the file list.
